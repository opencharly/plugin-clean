# 2026.322.1216 — feat(clean): reclaim the builder's persistent cache with --build-cache

## Summary

`charly clean` could not reclaim the buildkitd daemon's persistent `--root`, so a corrupt store cost
a hand-written `sudo rm -rf` over 301 708 container-owned files and 105 GiB
(opencharly/plugin-clean#23). `sdk/buildkitdrive` owns that root at `CacheDir()/buildkitd`
(`StateRoot`). It is not one of charly's stores — a store tree IS an OCI Image Layout and nothing
else (D-STORE-3), while this tree carries no `oci-layout` marker and MUST carry `buildkitd.lock` —
so every existing category missed it by construction: `--images` prunes the engine's storage,
`--check` sweeps `.check/` run dirs, `--deep` purges dangling engine images, `--cache` walks the
OCI-layout stores under the cache root, `--scopes` reaps systemd build scopes.

This change adds the `--build-cache` category, with two instruments behind one flag:

- **The live state root**, removed only when no daemon owns it. A running `buildkitd` holds an
  exclusive flock on `<root>/buildkitd.lock` for its whole life — that lock is how BuildKit
  enforces one daemon per root — so the lock IS the holder's liveness signal. The sweep SEIZES it
  before it touches the root (so no daemon can start halfway through) and refuses, naming the
  daemon by its lock and its socket, when it cannot. A lock dies with its holder (D-STORE-7), so a
  store left by a crashed daemon is reclaimable without asking anyone.
- **Every quarantined sibling** (`buildkitd.broken-*`), reclaimed unconditionally: a store is only
  quarantined once it has been abandoned, so there is nothing to race. The category recognizes the
  name without producing it — quarantining is a recovery decision for the store's owner — which is
  what gives an improvised directory an owner instead of leaving a corpse nobody dares touch.

Bytes are reported per root, `--dry-run` reports the same figures and touches nothing (it does not
even create the lock file to ask who owns the root), and a bare `charly clean` never runs it. A
tree this user cannot delete WHOLE — a rootless build leaves its store owned by container-mapped
UIDs — is reported BY NAME with the blocking path and the uid that owns it, and left exactly as it
was: the walk that measures a root also decides whether a whole-tree removal is possible, so a store
is never half-deleted. Both paths come from `sdk/buildkitdrive`; nothing here builds a
`<cache>/buildkitd` path by hand, and the category needs neither the container engine nor the
resolved keep-defaults.

The category set itself moves into the schema. `schema/clean.cue` declares
`#CleanPlugin.categories` — one row per category with its flag word, its one-line contract, `bare:`
(a plain `charly clean` runs it) and `implies:` (naming this one also runs those) — and the Go
grammar is DERIVED from it: `newCleanFlagSet` registers one flag per row with the row's contract as
its help text, and `cleanCategories` resolves the run set from `bare:`/`implies:`. The old
hand-written `anyCategory := …` chain and `doScopes = …` rule are gone, so a category is now a row
instead of an edit to a discipline every reader had to re-derive.
