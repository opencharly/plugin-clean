# 2026.287.2222 — feat(clean)!: the `cache` category retires DECLARED cache roots — one record, one sweep (closes charly-registry#11's plugin-clean half)

## Summary

**The plugin-clean half of `charly-registry#11`'s close.** The orphan-sweep ruling needed **two instruments, each the right type for its object**, and this lands the second one.

**Why a declared record rather than the discovery mechanism — measured, and it refuted my own earlier claim.** `storekit.OrphanedLayouts` (landed in `sdk#394`, tag `v0.2026287.2117`) DISCOVERS layout trees by the marker `NamedStores()` tests for — the right mechanism for a root whose children are layouts, which is why `charly-registry`'s `cache sweep` keeps using it. The pre-rename root is a **different shape**:

```
$ find ~/.cache/charly/images -type f | head -2
/home/atrawog/.cache/charly/images/sha256/16333ee0c00fc65e025a2a4f839703ad37a74728832977fbdf080984de1b8e5a
/home/atrawog/.cache/charly/images/sha256/9cb701c20b595f4442ba074b2ec924f396f4c474084608116901ce3098ebfe3d
$ find ~/.cache/charly/images -name oci-layout | wc -l
0                                        # files: 2, dirs: 1, 3.5M — a CONTENT-ADDRESSED BLOB STORE
$ OrphanedLayouts(~/.cache/charly/images)  -> 0 orphan(s), err=<nil>
```

The discovery mechanism returns **zero** there, and correctly so. Deciding that such a root is **retired** is **policy**, and widening the predicate to swallow it would be policy wearing a mechanism's name.

- **`retiredCacheRoots()` — the ONE record**: a single path element under the cache root, **why** it is retired, and **where its content went** (re-ingest with `charly cache ingest <ref>`; the content lands in the shared named store `<cache root>/registry`, keyed by the full ref). Adding an entry is the whole procedure for retiring another root.
- **`sweepRetiredCacheRoots(dryRun)`** — the same **report-then-remove** idiom as the rest of the category: a dry run SIZES each retired root and removes nothing; a real run removes it; a root that is already gone is reported **ABSENT**, not as an error, because "already swept" is the state a re-run reaches.
- The path goes through **`storekit.StoreDir`** — the ONE resolver, which validates the name as a single path element (a retired root can never escape the cache root) and honours `CHARLY_CACHE_DIR`.
- **`charly clean --cache` reports each retired root's state** (`would remove N` / `removed N` / `absent (already swept)`) beside the store GC — an operator asking what the cache holds is asking about both. No new flag and no new verb: the sweep rides the existing `--cache` category.
- The result rides a **LOCAL field** on the CLI's outcome struct, never `spec.RetentionReply`: that is a contract type owned by `spec`, and a sweep of this repo's own retired roots does not belong on a reply every peer plugin decodes.
- **Pin bump `sdk v0.2026266.1111 → v0.2026287.2117`** (the mechanism's tag — merged and tagged, Policy B), which drags `spec v0.2026266.2126 → v0.2026287.1529`.
- **`charly.yml`** — this repo's FIRST `disposable: true` bed (`check-clean-cache-roots`) + its `kind:local` template (see *How tested*; `AGENTS.md` names no bed for this repo — the org-level witness is charly's).
- **`.gitignore`** (+3) — ignores `.check/`, where the bed RETAINS its run evidence and its step log; without it every bed run leaves untracked files, and the umbrella ignores the same path for the same reason.
