# 2026.327.1025 — feat(clean): an --exports category removes the builder's leftover OCI export archives

## Summary

`charly clean` gains a schema-declared **`--exports`** category that reclaims the builder's
leftover **intermediate OCI export archives**.

Every image build stages its result as an OCI layout archive under the builder's state root
(`buildkitdrive.StageDir`), bridges it into the run engine, and deletes it. The archive has one
consumer and no later build reuses its name, so whatever stays is debris: a build that failed (the
exporter opens its destination before the solve completes, so an ENOSPC leaves a partial file), a
bridge that failed, a crash or a kill. `--build-cache` cannot cover it — that category reclaims the
**whole** state root and therefore refuses while the daemon holds its one-instance lock, which a
long-lived daemon always does. Measured on a host with a build history: **71 archives, 68 GiB**, and
an export that finally failed on a full disk under a path nobody recognised as a leak
(opencharly/plugin-build#64).

**Two guards, both load-bearing:**

1. **No live build** — the sweep declines wholesale while any build is live (`liveBuildFloor`, the
   same guard every destructive category uses) and prints the guard's decision **in place of** the
   count, so a declined sweep cannot read like an empty one.
2. **No open handle** — an archive a process holds open is named and left alone. The lock alone is
   not enough: measured, `~/.cache/charly/locks/builds` was **empty** while a `charly box build` was
   mid-resolve, and a `podman load` holds its archive open exactly while it must not be removed.

The category is a row in `schema/clean.cue` (`bare: true`), so the CLI grammar and the resolved
plan are **derived** from it (SDD); the archive/temp name predicate, the `/proc` open-handle scan
and the sweep live in `exports.go`; `command.go` renders the report. The clean skill
(`.agents/skills/clean/SKILL.md`) and the candy description are corrected at source.

No DESIGN shape is added: the directory still resolves through `buildkitdrive.StageDir` (D-STORE-1's
one resolver), and the category set stays the plugin's own declared surface.

## Change classification

Feature (`feat`), no breaking change. `--exports` is additive and `bare: true`, so a plain
`charly clean` now also reclaims leftover export archives — which is the point — and a host with a
live build sees the sweep decline rather than act. Rollback is a revert of this commit.
