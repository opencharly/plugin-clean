# 2026.288.2246 — fix(clean): make --cache reach the storekit store root too

## Summary

`charly clean --cache` enumerated **one** root and swept **one** store. There are two of each:

```
spec/cache   StoreRoot():  $CHARLY_CACHE_DIR  else  ** ~/.config/charly/cache/ **
storekit     CacheDir():   $CHARLY_CACHE_DIR  else  ** ~/.cache/charly **
```

**With the override unset — the live-host case — those are different directories**, so a store the one-store migration writes was invisible to the sweep. *Measured on this host: `charly clean --cache` reclaimed **5 664 unreferenced blobs (~106 MiB)** from the config root while `storekit.NamedStores()` over the cache root reported stores `spec/cache` could not see.* That asymmetry is this issue.

**The fix** adds a second half that walks `storekit.NamedStores()` and, per store, lists `UnreferencedBlobs()` then calls `RemoveBlob()` for each candidate — *the split `opencharly/sdk#416` landed, where discovery and removal stay separate so a sweep's destructive half sits with the surface that also reports it.* **Producer-first:** the pin moves to the tag carrying that surface, `sdk v0.2026287.2213 → v0.2026288.2236`.

## The roots can COINCIDE, and then the second half must not run

*Both resolvers honour `CHARLY_CACHE_DIR`, so with it set they name the **same** directory.* A second loop there would enumerate the layouts the first already swept, **count them twice**, and hand `storekit` a `spec/cache` layout to delete from.

> ***My first draft did exactly that, and the existing test failed naming stores it had never created.***

**So the halves must PARTITION the stores rather than overlap.** `sameStoreRoot()` compares the **resolved paths** — *not the environment variable* — and skips the second half when they agree; comparing resolved paths keeps it true if either resolver changes, and a resolver error reports "not the same root" so a broken root is never hidden behind a skip.

## How tested

**Coverage is two tests, because neither half can be covered by one fixture — one test pins one root:**

| test | root setup | which half it covers |
|---|---|---|
| `TestGCCacheStores` *(existing)* | `CHARLY_CACHE_DIR` set → roots agree | **half one**; half two *correctly skips* |
| `TestGCCacheStoresReachesTheStorekitRoot` *(new)* | unset; `XDG_CACHE_HOME` and `XDG_CONFIG_HOME` pointed apart | **half two** |

The new test **asserts its own premise** — that the roots genuinely differ — before relying on it, *so it cannot silently degrade into a copy of the other.* It then plants a `storekit` store with a superseded payload and asserts:

```
1. the dry run REACHES the store from the cache root, reports the reclaim, and removes nothing;
2. the real run removes exactly that set, and the figures AGREE between the two runs;
3. the LIVE payload survives — the assertion that catches a sweep subtracting the wrong set.
```

**It fails without the change:** *before it, `gcCacheStores` returned nothing for a `storekit` store.*

```
$ go test ./... -run TestGCCacheStores -v
--- PASS: TestGCCacheStoresReachesTheStorekitRoot
--- PASS: TestGCCacheStores
ok  github.com/opencharly/plugin-clean/candy/plugin-clean   0.015s
```

**And the numbers taught me the shape of the leak a second time, independently:** *the new test first asserted the payload's 22 bytes and measured **158** — the extra 136 is the superseded **entry manifest**, because a re-put orphans two blobs, not one. The assertion now states that property (`RemovedBlobs == 2`, bytes **at least** the payload's) instead of a total that would hard-code `storekit`'s manifest encoding.*

## A finding this change measured, and did not paper over

**`storekit` READS the `oci-layout` marker but never writes it.** *`PutBlob`/`PutEntry` create `blobs/` and `index.json` and stop, while `NamedStores()` enumerates on that marker alone* — so a store created through `storekit`'s own writers is invisible to its own enumeration until the marker exists. **Measured while building this test's fixture, which therefore writes the marker by hand:**

```
storekit.CacheDir = "/tmp/probe-cache/charly"       # XDG honoured
store dir entries:  blobs · index.json              # NO oci-layout marker
storekit.NamedStores = []                          # hence nothing enumerated
```

*`spec/cache`'s sibling writes it in its `Layout` constructor.* **Filed separately rather than fixed here**, because it is a defect in another repo's package and this change's R10 story does not need it.
