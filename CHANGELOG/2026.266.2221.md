# 2026.266.2221 — feat(clean): add the `cache` retention category (CAS ArtifactStore GC)

## Summary

Add the `cache` retention category — `charly clean --cache`, the last category of the plan that folds every cache onto the content-addressed `spec/cache` ArtifactStore. A replaced or deleted ArtifactStore entry leaves its superseded blobs behind (content addressing means a new key is a NEW manifest + blobs; the old ones stay unreferenced until reclaimed), and `Layout.GC()` already knows how to reclaim them. This is the consumer leg of the CAS-retention cutover (producer: opencharly/spec#151, merged + tagged `v0.2026266.2126`).

- `retention.go`: `gcCacheStores(dryRun)` enumerates `cache.NamedStores()` and runs each store's own `GCStats`, reporting `name`/`entries`/`removed_blobs`/`removed_bytes` via the new `spec.CacheStoreInfo`. No live-build guard is needed — this touches only the CAS blob store, never the podman image store the guard protects. An empty/absent cache root is an empty list, never an error.
- `command.go`: the `--cache` flag joins the category gate. The cache category needs **no** resolved keep-defaults and **no** engine binary, so it runs even out-of-process (only images/check/deep need the loader-resolved defaults). The report prints one line per store, or an explicit `cache: no named cache stores found`.
- `charly.yml`: the plan + description name the `--cache` category.
- `go.mod`/`go.sum`: pin `spec v0.2026266.2126` (the merged CAS-retention wire tag) + `sdk v0.2026266.1111`. The `spec` bump pulls two transitive indirect requires — `github.com/opencontainers/go-digest v1.0.0` and `github.com/opencontainers/image-spec v1.1.1` — which the `spec/cache` ArtifactStore imports; they are transitive from `spec v0.2026266.2126`, not chosen here.
- **Purely additive**: `--cache` is opt-in-only (like `--deep`), so a plain `charly clean` is unchanged.
